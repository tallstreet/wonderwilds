# Campaign authority and adoption

The campaign is an opt-in aggregate, separate from legacy story checkpoints. A
profile transaction locks the profile, canonical companion state, then campaign
checkpoint in that order. Commands, receipts, learning completion and canonical
recruitment commit together. Existing pending legacy work must finish before
adoption. No historical grants or XP are inferred and no old state is reset.

The pure domain receives a read-only projection of canonical companion IDs and
levels. Its team IDs, energy, encounters, resources, flags and grant references
are expedition state, never a second ownership/XP ledger. Recruitment returns
canonical grant intents to the API, which resolves already-owned IDs without a
duplicate reward. Learning evidence remains in its existing assessed stream.
Learning actions require an API verified completion bound to action, recipient,
content version and rules version; client claims cannot satisfy this gate.

Each adopted checkpoint pins immutable content and rules versions. Unknown or
mismatched versions fail explicitly without resetting progress. Encounters pin
those versions through the containing checkpoint. Commands are evaluated against
a cloned state: rejected actions cannot consume resources. The API supplies
profile ownership, expected revisions and durable command-id receipts; retries
return the original committed result. Public snapshots contain executable legal
actions and dialogue, never assessment answer keys.

Camp recovery is free. Forage refreshes only on first completion of an authored
project/trial; action grant IDs and encounter first-win IDs prevent replay farming.
Failure returns to the last visited camp with restored expedition energy;
consumed optional equipment stays consumed. Mandatory encounters lend renewable
attempt-local keeper charges. Every starter has a resource-free tactical route.

## Executable mechanics and public projection

The immutable definition contains typed routes, predicates, resource deltas,
encounter boards, recipient-bound milestones and field methods. Runtime rejects
unsupported kinds, references, rules and invalid board bounds. Quest prose cannot
create a mechanic. Puzzle configuration is saved as finite named flags; its
internal goal map is removed from public legal-action projections. All three
routing/ordering puzzles support configuration, failure feedback, reset and retry.

Field actions distinguish a licensed matching travelling companion from the
permanent tool alternative. The route graph requires the resulting path flag.
Neither a particular starter nor academic mastery is necessary. Encounter victory
precedes the current hazard; phase affinity changes on the following turn. Keeper
charges are attempt-local. Practice temporarily binds the named starter and
restores the previous travelling team without canonical ownership grants.

Care memories never grant XP. Level-three technique choices are reversible at
camp: one free signature each expedition or a stronger partner rally. All owned
friends recover at camp, including those outside the travelling pair. Retreat
returns to the last visited camp and preserves spent optional items. Bounded
guidance searches visible supply-free tactics and recommends retreat when its
finite search cannot find a continuation. It never changes game rewards.

Four contextual assessed milestones per companion use canonical grant aliases.
The campaign stores their references and narrative outcomes; canonical companion
records alone own resulting XP, level and selected appearance. A required project
that shares an already-earned milestone still completes without awarding XP twice.
Declining recruitment saves a memory and retains the invitation; already-owned
companions are excluded from recruit grants. Neither offline time nor care menus
create a resource refresh or progression grant.
