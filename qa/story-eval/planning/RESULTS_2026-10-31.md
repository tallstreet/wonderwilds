# Current-model mission planning baseline — 31 October 2026

The deployed `wonderwilds` model can produce mechanically valid plans for the
existing authored opportunities without additional fine-tuning. It passed all
18 ordinary cases and 17 of 18 ordering-stress cases. This small, related corpus
does not establish reliable novel mission generation or justify a training job.

These are paired prompt variants, not 36 independent situations. One deterministic
request per case was made with temperature 0, low reasoning and a 2,048-token
output limit. No structured-output decoder, JSON repair or fallback credit was
used. All successful witnesses were replayed by the Rust engine. The provider
reported model alias `wonderwilds`; an immutable deployed weight revision was not
exposed, so these results are tied to this run and endpoint, not a verified weight hash.

The endpoint initially returned HTTP 503 `no upstreams available`; those attempts
are preserved separately as availability failures and excluded from these model
quality measurements. The later complete runs had no transport errors.

## Concrete failure

In `bank-series-062`, Bramble's wish is known, but the workshop path has not been
checked or cleared. With the condition vocabulary reversed, the model proposed:

1. Ask whether Bramble is ready (`bramble_ready`).
2. Clear loose branches (`workshop_path_clear`).
3. Walk with Bramble (`bramble_arrived`).
4. Welcome Bramble (`bramble_visit_shared`).

The supplied capability explicitly requires a clear path before readiness.
The domain enforces that dependency. No action sequence can first satisfy these
milestones in the proposed order, so the grader returns
`no_ordered_completion_path`. The ordinary-input plan correctly checks the path,
clears it, then asks about readiness. The reversed condition list is only a
vocabulary permutation: the world state and capabilities did not change.

## Qualitative inspection

The implementing assistant inspected all 36 outputs; this is not independent
human review, a calibrated narrative score or content approval.

- Plans retained the supported outcomes, and the ordinary run correctly skipped
  completed milestones and unnecessary wood/plank work in supplied/repaired cases.
- In the ordinary run, **81 of 84 milestone labels exactly copied the supplied
  condition descriptions**. This is useful contract following, but not evidence
  of original mission premises or broad creative variety.
- Some text remains unsuitable as final child-facing copy: `bridge_bank` appears
  in the gathering premise, and bridge labels use technical phrases such as
  “compatible wood.” Some goals are long multi-sentence instructions.
- Partial-progress premises sometimes repeat earlier instructions, such as
  gathering glow pebbles after the pebbles are already collected. Milestones adapt
  correctly, but narrative context needs better handling.
- The supplied-planks case unnecessarily lists the woodcutter as a participant
  even though the remaining steps only need bridge repair and crossing with Pip.
  Known-character validation alone cannot detect this narrative mismatch.

## Decision

Do not fine-tune yet based on this result. First test a prompt/context revision
that explicitly derives milestone dependencies from capability prerequisites and
separates completed background from remaining instructions. Keep this baseline
frozen for comparison. Broaden the evaluation with several available opportunities,
unseen combinations and independently reviewed narrative quality before deciding
whether planning-specific training is warranted. Existing scene-writing evaluations
must also remain regression checks if weights are later changed.

The current harness only searches the existing authored action menu. It does not
install the proposed plan in the runtime, simulate arbitrary new mechanics or
prove recovery after all possible player deviations. All seven mission families
are related to existing scene-training material.
